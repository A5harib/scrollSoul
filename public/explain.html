SCROLLSOUL
Neural Architecture & Flow Explainer (SQLite Backed)

This document tracks and explains the architectural design of the ScrollSoul application. The app leverages a robust native SQLite database for data persistence and analytical query performance, while shifting OCR API calls, primary/fallback model routing, and settled scroll timing completely to JavaScript.

1. The Architecture: Hybrid native SQLite & JS Business Flow

The native Android layer acts as the Accessibility Event emitter and high-performance persistence engine (SQLite). JavaScript manages the high-level business flows and OCR pipeline orchestration.

Native SQLite Engine
  • TrackerDatabaseHelper: Stores tracked reels, watch times, engagement details, and thumbnails.
  • SQL Query Calculations: Highly optimized queries for today's count, hourly charts, top keyword distributions, and top creators.
  • Accessibility screenshotting: Native API Level 30 screenshot capture returning compressed JPEG base64 to JS.
JS Orchestrator
  • reelsStore.ts: Acts as a TypeScript proxy that delegates all load, save, and aggregate queries directly to native SQLite methods.
  • Groq OCR: Coordinates HTTP Vision request to Groq vision model with fallback.
  • Settled scroll: Debounces scroll events to guarantee OCR is only called when viewing a reel for >1.5 seconds.

2. Scroll Settling & OCR Optimization

To prevent executing heavy OCR calls when users are scanning through reels at rapid speeds, we introduce a Settled Scroll Timer on the JavaScript thread.

[Scroll Event received from Native Service] │ ▼ [Reset Debounce Timer (1.5s)] │ ├─► User scrolls again before 1.5s? ────► [Cancel old timer & Reset] │ ▼ [Timer Fires: Settled!] │ ▼ [Scrape current UI username/caption] │ ▼ [Is this same as last processed reel?] ──► Yes ──► [Skip OCR (Optimized!)] │ ▼ No [ReelsTrackerModule.takeScreenshot()] │ ▼ [Invoke Groq OCR Pipeline]

3. OCR LLM Pipeline

We send the screenshot as a base64 string to Groq's completions API. If the primary model fails or encounters rate limits, we fallback to the secondary model.

Primary: meta-llama/llama-4-scout-17b-16e-instruct ──► Fallback: qwen/qwen3.6-27b

4. Configuration & Deployment

Groq API Key Instructions:

To active the Groq vision OCR pipeline, set the environment variable GROQ_API_KEY on your system, or assign it directly inside useReelsTracker.ts on line 19:

const GROQ_API_KEY = process.env.GROQ_API_KEY || "YOUR_GROQ_API_KEY_HERE";

Run the build locally to deploy the optimized app:

npm run android
