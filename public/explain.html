SCROLLSOUL
Neural Architecture & Flow Explainer

This document tracks and explains the architectural shift of the ScrollSoul application. We are moving core logic out of Java to JavaScript to make the application simpler, more performant, and flexible. We are also introducing remote Groq OCR with LLM fallbacks and a settled scroll timing mechanism.

1. The Shift: Java to JavaScript

We are significantly thinning down the native Android layer by removing SQLite database operations, MLKit libraries, and OCR processing code from Java. Instead, the native layer becomes a lightweight proxy for events and OS-level operations (Accessibility and screenshotting).

Before (Java Heavy)
  • SQLite Database: Tracked reels, durations, today counts, and hourly calculations executed in native Java.
  • OCR engine: Local MLKit dependency built into Android APK to parse screen text.
  • String Cleanup: Heuristics for stripping UI strings written in verbose Java utility functions.
After (JS Centric)
  • Lightweight Storage: Store reel history in a JSON database (`reels.json`) on the device. Read/write via tiny Native Modules methods.
  • Groq OCR: Call Groq API over HTTP from JavaScript. No heavy local packages.
  • Flexible Analytics: Stats, hourly activity, and keyword counts computed directly in JS arrays.

2. Scroll Settling & OCR Optimization

To prevent executing heavy OCR calls when users are scanning through reels at rapid speeds, we introduce a Settled Scroll Timer on the JavaScript thread.

[Scroll Event received from Native Service] │ ▼ [Reset Debounce Timer (1.5s)] │ ├─► User scrolls again before 1.5s? ────► [Cancel old timer & Reset] │ ▼ [Timer Fires: Settled!] │ ▼ [Scrape current UI username/caption] │ ▼ [Is this same as last processed reel?] ──► Yes ──► [Skip OCR (Optimized!)] │ ▼ No [ReelsTrackerModule.takeScreenshot()] │ ▼ [Invoke Groq OCR Pipeline]

3. OCR LLM Pipeline

We send the screenshot as a base64 string to Groq's completions API. If the primary model fails or encounters rate limits, we fallback to the secondary model.

Primary: meta-llama/llama-4-scout-17b-16e-instruct ──► Fallback: qwen/qwen3.6-27b

4. Configuration & Deployment

Groq API Key Instructions:

To active the Groq vision OCR pipeline, set the environment variable GROQ_API_KEY on your system, or assign it directly inside useReelsTracker.ts on line 13:

const GROQ_API_KEY = process.env.GROQ_API_KEY || "YOUR_GROQ_API_KEY_HERE";

Run the build locally to deploy the optimized app:

npm run android
